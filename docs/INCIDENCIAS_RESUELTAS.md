# Fase 7: Matriz de incidencias resueltas

Especificación de origen: `docs/referencia/incidencias_mr_black.pdf` (24 incidencias).
Las causas raíz en el prototipo están detalladas en `docs/ANALISIS.md` §5.

Cada incidencia se verificó en dos niveles:

- **Pytest** (`backend/tests/`) contra PostgreSQL real, llamando a la API directamente (sin
  pasar por la interfaz). Así se comprueba que la regla no se puede saltar desde el navegador.
- **E2E** (`e2e/e2e_check.py`) con Chromium headless sobre el stack Docker completo.

## Defectos adicionales corregidos (no listados en el PDF)

| Defecto | Solución |
|---|---|
| Solapamiento de citas por duración (P4) | La disponibilidad considera la duración completa y PostgreSQL tiene una restricción de exclusión `tstzrange` |
| Reprogramar cancelaba la cita antes de elegir el horario nuevo (P5) | Reprogramación atómica: la cita solo cambia si el nuevo horario se confirma (`test_failed_reschedule_keeps_original`) |
| Sobreventa con compras simultáneas | `SELECT … FOR UPDATE` + `populate_existing`, más `CHECK stock >= 0`. Este error lo encontró la propia suite durante el desarrollo y quedó corregido |
| Contraseñas en texto plano y sesión en `localStorage` | Argon2id, cookie HttpOnly, sesión revocable y CSRF |
